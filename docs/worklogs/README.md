# Work logs

Lightweight records for nontrivial multi-phase changes, non-obvious design choices, and
performance experiments; small fixes need none. Name files `YYYY-MM-DD-<topic>.md`, keep one per
change theme, and link it from the pull request.

Record the chosen approach and why, important alternatives, verification conclusions, and
remaining constraints. Do not list commands run, files read, or the chronology of edits
(rules/common/repository.md, "Work Logs And Design Records").
